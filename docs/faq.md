# Frequently Asked Questions (FAQ)

## 1. General Questions

### What is Antigravity Engineering Kit (AEK)?
AEK is a Rust-first, cross-platform engineering toolkit designed to enhance AI-assisted software development. It translates engineering rules, skills, MCP servers, and prompt optimization runbooks into the native formats of Google Gemini Antigravity, Claude Code, Cursor, and OpenCode.

### Does AEK require administrator or root privileges?
No. AEK installs and operates entirely within user-space (`%LOCALAPPDATA%\aek` on Windows, `~/.local/share/aek` or `~/.aek` on Linux/macOS). It never modifies system files or requires elevated permissions.

### Which operating systems are supported?
- **Windows**: x86_64 (Windows 10, 11, Windows Server 2019+)
- **Linux**: x86_64 (Ubuntu 22.04+, Debian 12+, Fedora, Arch)
- **macOS**: Apple Silicon (aarch64) and Intel (x86_64)

## 2. Multi-Agent Compatibility

### How does AEK support multiple AI coding agents?
AEK provides an extensible agent adapter architecture (`aek-agents`). Each adapter maps AEK's typed engineering concepts (rules, skills, MCP servers, prompts) into the agent's native format:
- **Google Antigravity**: Rules in `<appDataDir>/gemini/antigravity/rules`, skills, and native MCP configs.
- **Claude Code**: Single consolidated `CLAUDE.md`, `.claude/mcp.json`, and `.claude/settings.json`.
- **Cursor**: MDC rules in `.cursor/rules/*.mdc`, legacy `.cursorrules`, and `.cursor/mcp.json`.
- **OpenCode**: `AGENTS.md`, `.opencode/config.json`, and `.opencode/skills/`.

### What happens if I manually edited my `CLAUDE.md` or `.cursorrules`?
AEK uses an ownership manifest (`.aek/managed-agents.toml`) and SHA-256 hashes to track files it generated. When you run `aek agent sync`, you can choose a conflict resolution strategy:
- `KeepExisting`: Never overwrites user-modified files.
- `ReplaceManaged`: Only overwrites files previously generated by AEK that have not been manually altered.
- `Skip`: Skips any existing target file.
- `ManualResolution`: Prompts for manual intervention.

## 3. Performance & Resource Usage

### How much memory does AEK use?
AEK is written in idiomatic Rust and operates on-demand without background daemons. Its idle memory footprint is `<50 MB`, and peak memory during workspace validation is typically `<120 MB`, making it well-suited for 8 GB RAM developer laptops.

### Does AEK run a continuous background service?
No. AEK is an ephemeral command-line tool. It runs when invoked, completes its operation deterministically, and exits immediately.

---

## 4. Security & Privacy

### Does AEK send telemetry or code to remote servers?
No. AEK does not collect telemetry, track usage, or transmit code to remote servers. All rule resolution, skill discovery, validation, and configuration synchronization run 100% locally on your machine.

### How does AEK prevent command injection?
AEK's subprocess execution engine (`SafeCommand` in `aek-core`) passes command arguments as discrete arrays directly to the OS kernel (`CreateProcessW` on Windows, `execve` on Linux/macOS). Commands are never evaluated through shell string wrappers (`cmd.exe /c` or `sh -c`), preventing command injection.

## 5. Updates & Uninstallation

### How do I update AEK?
Run:
```bash
aek update check
aek update
```
If an update causes issues, you can instantly roll back to the previous version:
```bash
aek rollback
```

### How do I cleanly uninstall AEK?
Run:
```bash
aek uninstall --dry-run
aek uninstall
```
To purge configuration and backup files as well:
```bash
aek uninstall --purge
```
